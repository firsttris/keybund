# Code review, October 2026

Four reviewers (rendering/model, file writes, diagnostics, app layer) checked Keybund against the
OpenSSH and Git sources and reproduced every finding with the real `ssh`/`git` in a throw-away
HOME. This page records what was found, what was fixed (commits on `main` from `7074ed3` to
`57e70a3`), and what is still open – so the work can be picked up by anyone.

### Details on the open items

- `hostkeys::is_known` looks only in Keybund's file, `~/.ssh/known_hosts` and the system file. A
  user with `UserKnownHostsFile` under their own `Host *` gets "unknown" and Keybund writes to a file
  ssh never reads for GitHub. Fix: ask `ssh -G <host>` for `userknownhostsfile`.
- `is_known` ignores `known_hosts_per_profile = false` after a key was stored per profile (edge).
- Linked worktree inside a folder whose main repo is outside gets no key (documented, by git's rule).
- `edit`: `store::save` then `create_dir_all` – a failing mkdir exits 2 after the profile was saved.
- `archive_profile` in the app: a failing `apply_config` afterwards leaves configs referencing the
  old path until "Review & rewrite" (shown as error toast + pending footer, not silent).
- A language switch remounts the router, so a row that started a test cannot show the in-flight
  result (the test completes; backend state is right).
- AppImage environment (GTK_PATH etc.) reaching `ssh-askpass` was not testable here.
- Bitbucket greeting text could not be verified without network.
